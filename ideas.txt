Primary track: 03 — MCP & Agentic AI.
MCP is central: MIRAGE controls which world the agent’s tools connect to. It overlaps naturally with Blue Teaming, but the entire story is about securing agents and their tool use.
Here’s the idea in a concrete scenario.
A company has an AI finance assistant. An employee asks it to summarize outstanding invoices. One invoice contains a malicious instruction that diverts the assistant toward exporting the customer database.
MIRAGE sits between the agent and its tools. When an action crosses an enforced permission boundary, it blocks the real operation and routes the suspicious session into a synthetic company environment:
•⁠  ⁠The database contains fictional customers.
•⁠  ⁠The document store contains plausible fake contracts.
•⁠  ⁠The email tool delivers into an isolated mailbox.
•⁠  ⁠Credentials work only against simulated services.
•⁠  ⁠Destructive operations change only the simulated environment.
The twist is that the fake company stays consistent. A person mentioned in a contract also exists in the directory. Their invoices match the finance database. Their messages refer to those same invoices. AI generates the connected details as the suspicious agent explores.
That gives you something much more visually compelling than a red “attack blocked” alert: an agent wandering through a company that is being invented around it.
[19/09/26, 11:54:55 AM] Manas(134): What to build

A data-flow firewall for agent tool calls. It sits as a transparent proxy between any MCP client and its servers.

Here is the critical thing I found, and it changes the pitch. The obvious version of this project already exists. MCP-Scan from Invariant Labs does tool pinning, rug-pull detection, injection scanning, and a local guardrail gateway. It has traction and Snyk acquired it. A Snyk security leader speaks at this community. If you pitch "we built an MCP scanner," you will get asked about it and you will lose.

So do not build a classifier. Build provenance. Tag every piece of content entering the agent's context with its source, propagate that tag through the session, and block privileged calls whose inputs are tainted by untrusted origin. This maps to the lethal trifecta threat model: private data access, untrusted content, and an exfiltration path. Existing tools pattern-match the payload. You enforce the flow, which does not care how the attack is phrased.

That gives you one sentence that beats the incumbent:

Content classifiers fail on novel phrasing and encoding. Flow control does not read the text, so there is nothing to rephrase.
